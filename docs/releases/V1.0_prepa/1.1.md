# BC-1.1 — Intégration finale et validation fonctionnelle

# Objectif

Cette sous-issue réalise l'intégration complète de toutes les fonctionnalités prévues pour la version 1.0 de BadCalendar.

Elle a pour objectif de vérifier que les différents composants développés au cours des versions précédentes fonctionnent correctement ensemble et offrent une expérience utilisateur cohérente.

Aucune nouvelle fonctionnalité n'est développée.

---

# Contexte

Les versions précédentes ont permis de développer :

- le nouveau modèle métier Tournament ;
- Google Calendar ;
- les améliorations UX ;
- les filtres multi-valeurs ;
- les Usage Metrics.

Cette sous-issue consiste à valider l'ensemble du produit avant le lancement du pilote utilisateur.

---

# Vérifications fonctionnelles

Les scénarios suivants doivent être validés.

## Chargement de l'application

Vérifier que :

- l'application démarre correctement ;
- le chargement est fluide ;
- les erreurs sont correctement gérées ;
- la version affichée correspond à la version publiée.

---

## Consultation des compétitions

Vérifier que :

- les compétitions sont affichées chronologiquement ;
- le regroupement par mois fonctionne ;
- les événements passés sont masqués ;
- les cartes se replient et se déplient correctement.

---

## Filtres

Vérifier que :

- tous les filtres fonctionnent ;
- les filtres multi-valeurs produisent les résultats attendus ;
- la persistance des filtres fonctionne ;
- le bouton de réinitialisation fonctionne ;
- les états vides sont correctement affichés.

---

## Informations des compétitions

Vérifier que chaque carte affiche correctement :

- le type ;
- les dates ;
- le lieu ;
- les catégories ;
- la portée ;
- l'état des inscriptions ;
- les liens disponibles.

---

## Google Calendar

Vérifier que :

- l'export fonctionne ;
- toutes les informations sont présentes ;
- les événements sur plusieurs jours sont correctement créés ;
- le lien BadNet est présent dans la description.

---

## Google Maps

Vérifier que :

- le lieu ouvre correctement Google Maps ;
- les coordonnées sont cohérentes lorsque disponibles.

---

## BadNet

Vérifier que :

- chaque lien ouvre la bonne compétition ;
- aucune URL invalide n'est générée.

---

## Nouveautés

Vérifier que :

- les nouveaux tournois sont correctement identifiés ;
- les nouveautés disparaissent après la durée définie ;
- les modifications d'un tournoi existant ne créent pas de faux positifs.

---

## Usage Metrics

Vérifier que :

- tous les événements sont enregistrés ;
- le Dashboard est correctement alimenté ;
- les statistiques sont cohérentes.

---

## Responsive

Vérifier le comportement sur :

- smartphone Android ;
- smartphone iPhone (si disponible) ;
- tablette ;
- desktop.

---

# Vérifications techniques

Contrôler notamment :

- absence d'erreurs JavaScript ;
- absence de régressions ;
- cohérence des modèles métier ;
- cohérence des données envoyées au frontend.

# Release Checklist

Avant de clôturer cette sous-issue :

- toutes les fonctionnalités prévues pour la v1.0 sont présentes ;
- tous les critères d'acceptation des versions précédentes sont validés ;
- aucune anomalie bloquante n'est identifiée ;
- la documentation est synchronisée.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouvelles fonctionnalités ;
- améliorations UX supplémentaires ;
- optimisations non bloquantes.

Les éventuelles améliorations seront étudiées après le pilote.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- toutes les fonctionnalités de la v1.0 fonctionnent correctement ensemble ;
- aucune régression fonctionnelle n'est observée ;
- les tests manuels sont validés ;
- la documentation est complète et synchronisée ;
- la version est prête pour la campagne pilote.

---

# Livrable attendu

À l'issue de cette sous-issue :

- BadCalendar est entièrement intégré ;
- toutes les fonctionnalités prévues pour la v1.0 sont opérationnelles ;
- le produit est suffisamment stable pour être testé par des utilisateurs réels ;
- la campagne pilote peut être lancée.
