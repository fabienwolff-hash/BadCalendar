# BC-16.3 — Tableau de bord Usage Metrics

# Objectif

Cette sous-issue met en place le tableau de bord permettant d'analyser les métriques d'utilisation collectées par BadCalendar.

Le tableau de bord est construit dans Google Sheets à partir des données enregistrées dans l'onglet Logs.

L'objectif est de fournir une vision simple, exploitable et orientée produit des usages observés pendant la phase pilote.

---

# Contexte

Les événements d'utilisation sont désormais enregistrés par le backend.

Cette sous-issue consiste à exploiter ces données afin de produire des indicateurs facilitant l'analyse des comportements utilisateurs.

Le tableau de bord doit être entièrement calculé à partir des données présentes dans l'onglet Logs.

Aucune saisie manuelle n'est nécessaire.

---

# Architecture

Le classeur Google Sheets est composé de deux onglets.

## Logs

Cet onglet est alimenté automatiquement par le backend.

Chaque ligne correspond à un événement utilisateur.

Il constitue la source unique des données.

Aucune formule ne doit être ajoutée dans cet onglet.

---

## Dashboard

Cet onglet contient :

- les indicateurs clés ;
- les tableaux de synthèse ;
- les graphiques.

Toutes les informations sont calculées automatiquement à partir de l'onglet Logs.

---

# Indicateurs

Le tableau de bord présente notamment :

## Utilisation générale

- nombre total d'événements ;
- nombre total de sessions ;
- nombre moyen d'événements par session ;
- répartition des événements par type.

---

## Utilisation des filtres

Le tableau de bord affiche :

- nombre d'utilisations par filtre ;
- valeurs les plus sélectionnées ;
- fréquence de réinitialisation des filtres ;
- nombre de recherches sans résultat.

---

## Consultation

Le tableau de bord présente :

- nombre de cartes ouvertes ;
- tournois les plus consultés.

---

## Actions

Le tableau de bord présente :

- ouvertures BadNet ;
- ouvertures Google Maps ;
- exports Google Calendar.

---

## Évolution

Le tableau de bord présente une évolution hebdomadaire :

- des sessions ;
- des événements ;
- des principales actions.

Cette évolution permet d'observer l'adoption de l'application pendant le pilote.

---

# Présentation

Le Dashboard privilégie une présentation simple.

Les indicateurs principaux sont regroupés dans la partie supérieure.

Les tableaux détaillés sont placés en dessous.

Les graphiques facilitent la lecture des tendances.

---

# Calcul

Tous les indicateurs reposent exclusivement sur :

- QUERY ;
- COUNTIF ;
- COUNTIFS ;
- UNIQUE ;
- SORT ;
- FILTER ;
- ARRAYFORMULA.

Aucun script complémentaire n'est nécessaire.

---

# Performance

Le tableau de bord doit continuer à fonctionner avec plusieurs milliers d'événements.

Les formules doivent rester simples et facilement maintenables.

---

# Documentation

Le fonctionnement du Dashboard doit être documenté.

La documentation décrit :

- chaque indicateur ;
- sa formule de calcul ;
- son intérêt pour l'analyse produit.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- recommandations automatiques ;
- intelligence artificielle ;
- export des statistiques ;
- alertes automatiques.

Ces fonctionnalités pourront être étudiées dans les versions futures.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- le Dashboard est entièrement alimenté par l'onglet Logs ;
- tous les indicateurs sont calculés automatiquement ;
- les graphiques fonctionnent correctement ;
- aucune saisie manuelle n'est nécessaire ;
- la documentation est synchronisée.
