# BC-1.2 — Campagne pilote

# Objectif

Cette sous-issue organise la campagne pilote de BadCalendar auprès d'un groupe restreint de parents de joueurs de badminton.

L'objectif est de valider que l'application est intuitive, utile et répond aux besoins réels avant sa publication officielle.

Les retours qualitatifs des utilisateurs sont complétés par les Usage Metrics collectées automatiquement.

Aucune nouvelle fonctionnalité n'est développée.

---

# Contexte

La version 1.0 est désormais fonctionnellement complète.

Avant sa publication, une phase pilote permet de :

- identifier les éventuels points de friction ;
- mesurer la compréhension de l'interface ;
- confirmer les choix UX réalisés ;
- détecter les anomalies restantes.

Cette campagne constitue la dernière étape de validation du produit.

---

# Participants

La campagne est réalisée auprès d'un nombre limité d'utilisateurs représentatifs.

Elle comprend notamment :

- plusieurs parents de jeunes joueurs ;
- un enfant de 9 ans.

L'objectif n'est pas d'obtenir un échantillon statistique mais de recueillir des retours concrets.

---

# Déroulement

Chaque participant reçoit une courte présentation de BadCalendar.

L'application est ensuite utilisée librement.

Le développeur n'intervient pas pendant la navigation afin de ne pas influencer les comportements.

Les échanges peuvent être réalisés à distance.

---

# Scénarios proposés

Les participants sont invités à réaliser plusieurs actions représentatives :

- retrouver une compétition adaptée à leur enfant ;
- utiliser les filtres ;
- consulter une fiche compétition ;
- ouvrir BadNet ;
- ouvrir Google Maps ;
- ajouter une compétition à Google Calendar.

Les scénarios restent volontairement simples.

---

# Questionnaire

À l'issue de la session, chaque participant répond au questionnaire préparé.

Les questions portent notamment sur :

- la compréhension générale ;
- la facilité d'utilisation ;
- les difficultés rencontrées ;
- les fonctionnalités les plus utiles ;
- les améliorations souhaitées.

Les réponses libres sont privilégiées.

---

# Usage Metrics

Pendant toute la campagne, les Usage Metrics sont collectées automatiquement.

Les indicateurs permettent notamment d'observer :

- les filtres utilisés ;
- les cartes ouvertes ;
- les exports Google Calendar ;
- les ouvertures BadNet ;
- les ouvertures Google Maps ;
- les recherches sans résultat.

Ces données complètent les retours exprimés par les participants.

---

# Analyse

À l'issue de la campagne, les résultats sont analysés.

Les remarques sont classées en plusieurs catégories :

- anomalies ;
- problèmes UX ;
- incompréhensions ;
- idées d'amélioration ;
- suggestions hors périmètre.

Cette classification permettra de préparer les corrections de la BC-1.3.

---

# Documentation

Un compte rendu de la campagne est rédigé.

Il comprend notamment :

- les principaux enseignements ;
- les métriques observées ;
- les décisions prises ;
- les évolutions retenues ;
- les évolutions reportées.

Ce document servira de référence pour les versions futures.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- développement de nouvelles fonctionnalités ;
- corrections de bugs ;
- optimisation des performances.

Ces actions seront réalisées dans la BC-1.3.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- la campagne pilote est réalisée ;
- tous les questionnaires sont complétés ;
- les Usage Metrics sont collectées ;
- les retours sont analysés ;
- une liste priorisée des corrections est établie ;
- le compte rendu est rédigé.

---

# Livrable attendu

À l'issue de cette sous-issue :

- BadCalendar a été testé par des utilisateurs représentatifs ;
- les principaux points de friction sont identifiés ;
- les Usage Metrics complètent les retours utilisateurs ;
- une feuille de route des corrections est disponible pour la BC-1.3.
