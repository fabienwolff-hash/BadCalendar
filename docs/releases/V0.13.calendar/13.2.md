# BC-13.2 — Génération de l'événement Google Calendar

# Objectif

Cette sous-issue implémente la logique de génération d'un événement Google Calendar à partir d'un Tournament.

L'objectif est de produire une URL Google Calendar complète et valide permettant au parent d'ajouter une compétition dans son calendrier personnel en un clic.

Toute la logique métier est implémentée dans CalendarService.

---

# Contexte

CalendarService existe désormais.

Cette sous-issue consiste à transformer les propriétés d'un Tournament en un événement Google Calendar conforme aux spécifications définies pour BadCalendar.

L'utilisateur ne renseigne aucune information.

Toutes les données proviennent du modèle métier.

---

# Informations exportées

Chaque événement Google Calendar contient les informations suivantes.

## Titre

Le titre correspond au nom du tournoi.

Exemple :

```text
TDJ Nantes
```

Le titre ne comporte aucun préfixe.

---

## Date

L'événement couvre toute la durée de la compétition.

Exemple :

```text
Samedi 14 septembre
↓

Dimanche 15 septembre
```

Les stages de plusieurs jours sont donc correctement représentés.

---

## Heure

Tous les événements sont créés en mode :

```text
Toute la journée
```

Aucune heure de début ou de fin n'est renseignée.

---

## Lieu

Le champ "Lieu" est renseigné lorsque les informations sont disponibles.

Le format retenu est :

```text
Gymnase de la Chesnaie

12 rue des Sports

44000 Nantes
```

Les informations absentes sont simplement ignorées.

---

## Description

La description est générée automatiquement.

Elle contient uniquement des informations utiles au parent.

Ordre recommandé :

```text
Compétition de badminton

Lien BadNet

https://...

Google Maps

https://...

Ajouté depuis BadCalendar
```

Le texte reste volontairement concis.

---

# Gestion du lien Google Maps

Lorsque le lien Google Maps est disponible, il est ajouté dans la description.

Le champ "Lieu" reste indépendant.

Ainsi :

- Google Calendar affiche l'adresse ;
- le parent peut également ouvrir Google Maps directement depuis la description.

---

# Gestion du lien BadNet

Le lien BadNet est toujours ajouté lorsqu'il est connu.

Il constitue la référence officielle de la compétition.

---

# Données facultatives

Le service doit fonctionner même si certaines informations sont absentes.

Exemples :

- adresse inconnue ;
- salle inconnue ;
- Google Maps indisponible.

Dans ce cas :

- aucune erreur n'est générée ;
- les informations absentes sont simplement omises.

---

# Encodage

Tous les paramètres transmis à Google Calendar doivent être correctement encodés.

Les caractères spéciaux doivent être compatibles avec les URLs.

Cette responsabilité appartient exclusivement à CalendarService.

---

# Robustesse

La génération doit être déterministe.

Pour un même Tournament, la même URL doit toujours être produite.

Aucune donnée dépendant de l'utilisateur ou du navigateur ne doit intervenir.

---

# Évolutivité

La structure de CalendarService doit permettre d'ajouter ultérieurement :

- Outlook Calendar ;
- Apple Calendar ;
- export ICS.

Sans modifier la logique métier existante.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- bouton Google Calendar ;
- ouverture du navigateur ;
- analytics ;
- instrumentation ;
- tests fonctionnels utilisateur.

Ces sujets seront traités dans les sous-issues suivantes.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- le titre est correctement généré ;
- la durée de la compétition est correctement exportée ;
- l'événement est créé en mode "Toute la journée" ;
- le lieu est correctement renseigné lorsqu'il est disponible ;
- le lien BadNet est présent ;
- le lien Google Maps est présent lorsqu'il est connu ;
- les données absentes sont correctement gérées ;
- l'URL produite est valide.
