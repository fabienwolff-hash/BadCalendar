# BC-15.3 — Intégration des filtres multi-valeurs

# Objectif

Cette sous-issue intègre le nouveau système de filtres multi-valeurs dans l'interface utilisateur.

L'objectif est de permettre au parent de sélectionner plusieurs valeurs pour un même filtre tout en conservant une interface simple, rapide et adaptée au mobile.

Le moteur de filtrage est déjà disponible.

Cette sous-issue concerne uniquement l'expérience utilisateur.

---

# Contexte

Les filtres constituent le principal moyen de retrouver rapidement une compétition.

L'interface doit permettre de sélectionner plusieurs valeurs sans rendre l'utilisation plus complexe.

Le comportement doit rester naturel dès la première utilisation.

---

# Principes UX

Les filtres respectent les principes suivants :

- sélection immédiate ;
- aucune validation supplémentaire ;
- aucun bouton "Appliquer" ;
- filtrage instantané ;
- comportement identique sur mobile et desktop.

---

# Filtres concernés

Les filtres suivants deviennent multi-valeurs :

- Catégorie
- Type
- Portée
- État des inscriptions

Le filtre Mois reste mono-valeur.

---

# Sélection

Chaque valeur peut être :

- sélectionnée ;
- désélectionnée.

Une nouvelle sélection met immédiatement à jour la liste des compétitions.

Aucune action supplémentaire n'est nécessaire.

---

# Représentation visuelle

Les valeurs sélectionnées sont clairement identifiables.

Le style graphique reste cohérent avec le reste de l'application.

L'utilisateur distingue immédiatement :

- les valeurs sélectionnées ;
- les valeurs non sélectionnées.

---

# Filtres repliés

Lorsque le panneau des filtres est replié :

- le résumé actuel reste affiché ;
- le comportement existant est conservé.

L'objectif est de limiter l'encombrement visuel.

---

# Persistance

Les filtres persistés continuent de fonctionner.

Pour les filtres multi-valeurs, l'ensemble des valeurs sélectionnées est mémorisé.

Les filtres non persistés restent réinitialisés à chaque ouverture.

---

# Réinitialisation

Le bouton **Réinitialiser les filtres** :

- désélectionne toutes les valeurs ;
- supprime les préférences persistées ;
- restaure le comportement par défaut.

---

# Performance

Le filtrage doit rester instantané.

Le nombre de valeurs sélectionnées ne doit pas modifier perceptiblement le temps de réponse.

---

# Responsive

Le comportement est identique sur :

- smartphone ;
- tablette ;
- desktop.

Les contrôles restent facilement utilisables au doigt.

---

# Accessibilité

Chaque valeur reste facilement sélectionnable.

La zone tactile est suffisamment grande sur mobile.

Le contraste visuel permet d'identifier rapidement les valeurs actives.

---

# Architecture

Le frontend :

- affiche les filtres ;
- transmet les valeurs sélectionnées au FilterService ;
- affiche les résultats retournés.

Aucune logique métier supplémentaire n'est introduite dans les composants d'interface.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouveaux critères de filtrage ;
- analytics ;
- nouvelles préférences utilisateur ;
- optimisation des performances.

Ces évolutions seront étudiées ultérieurement.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- les quatre filtres concernés permettent plusieurs sélections ;
- le filtre Mois reste mono-valeur ;
- le filtrage est instantané ;
- les préférences persistées continuent de fonctionner ;
- le bouton "Réinitialiser les filtres" fonctionne correctement ;
- le comportement est identique sur mobile et desktop ;
- aucune régression fonctionnelle n'est observée.
