# BC-15.2 — Implémentation du moteur de filtrage

# Objectif

Cette sous-issue implémente le nouveau moteur de filtrage capable de traiter des filtres multi-valeurs.

Le moteur applique les règles métier définies dans la BC-15.1 et détermine les tournois à afficher.

Aucune évolution de l'interface utilisateur n'est réalisée dans cette sous-issue.

---

# Contexte

Le modèle de filtres accepte désormais plusieurs valeurs par critère.

Le moteur de filtrage doit être adapté afin d'exploiter cette nouvelle représentation tout en conservant les performances et le comportement existants.

---

# Principes

Le moteur de filtrage repose sur les principes suivants :

- chaque filtre est indépendant ;
- un filtre inactif ne restreint jamais les résultats ;
- plusieurs valeurs d'un même filtre sont combinées avec un opérateur **OU** ;
- plusieurs filtres sont combinés avec un opérateur **ET**.

Ces règles sont identiques quel que soit le nombre de valeurs sélectionnées.

---

# Fonctionnement

Pour chaque tournoi :

1. chaque filtre actif est évalué ;
2. si le tournoi satisfait tous les filtres actifs, il est conservé ;
3. sinon il est exclu de la liste.

Le résultat final est obtenu après une unique évaluation.

---

# Règles métier

## Catégorie

Un tournoi est conservé si au moins une des catégories du tournoi correspond à une catégorie sélectionnée.

---

## Type

Un tournoi est conservé si son type correspond à l'une des valeurs sélectionnées.

---

## Portée

Un tournoi est conservé si sa portée correspond à l'une des valeurs sélectionnées.

---

## État des inscriptions

Un tournoi est conservé si son état correspond à l'une des valeurs sélectionnées.

---

## Mois

Le filtre Mois conserve son fonctionnement actuel.

Une seule valeur est sélectionnable.

---

# Ordre d'application

L'ordre d'évaluation des filtres n'a aucune incidence sur le résultat.

Le moteur doit produire exactement les mêmes résultats quel que soit l'ordre dans lequel les filtres sont parcourus.

---

# Cas particuliers

## Aucun filtre actif

Tous les tournois sont affichés.

---

## Une seule valeur

Le comportement est identique à celui de la version précédente.

---

## Plusieurs valeurs

Le tournoi est conservé dès qu'une correspondance est trouvée.

Il est inutile de poursuivre la recherche pour ce filtre.

---

## Aucun résultat

Le moteur retourne une liste vide.

L'affichage du message utilisateur reste de la responsabilité du frontend.

---

# Architecture

Le moteur de filtrage constitue la seule implémentation des règles de sélection.

Le frontend ne réalise aucun calcul métier.

Il transmet uniquement les filtres sélectionnés et affiche les résultats retournés.

---

# Performance

Le filtrage doit rester instantané.

Dès qu'un tournoi ne satisfait plus un filtre actif, son évaluation peut être interrompue.

Aucune optimisation complexe n'est nécessaire compte tenu du volume limité de compétitions.

La lisibilité du code reste prioritaire.

---

# Évolutivité

Le moteur doit permettre l'ajout futur de nouveaux critères de filtrage sans modifier son fonctionnement général.

Chaque nouveau filtre doit pouvoir être ajouté de manière indépendante.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouvelle interface de sélection ;
- persistance des filtres ;
- analytics ;
- modifications graphiques.

Ces sujets seront traités dans les sous-issues suivantes.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- les filtres multi-valeurs sont correctement interprétés ;
- les règles OU/ET sont respectées ;
- le filtre Mois conserve son comportement actuel ;
- les filtres inactifs ne limitent pas les résultats ;
- les performances restent comparables à la version précédente ;
- aucune régression fonctionnelle n'est observée.
