# BC-14.2 — Amélioration des cartes de compétition

# Objectif

Cette sous-issue améliore la lisibilité des cartes de compétition afin de permettre au parent d'identifier rapidement les informations essentielles.

L'objectif est de faciliter la prise de décision sans augmenter la quantité d'informations affichées.

La priorité est donnée à la hiérarchie visuelle et à la simplicité.

---

# Contexte

Les cartes constituent l'élément central de BadCalendar.

Chaque consultation passe par leur lecture.

Une carte doit permettre au parent de répondre rapidement aux questions suivantes :

- De quel tournoi s'agit-il ?
- Quand a-t-il lieu ?
- Pour quelle catégorie ?
- Les inscriptions sont-elles ouvertes ?
- Est-ce une compétition qui m'intéresse ?

Les informations secondaires restent accessibles uniquement après dépliage.

---

# Principes UX

Les cartes respectent les principes suivants :

- afficher uniquement les informations essentielles lorsqu'elles sont repliées ;
- éviter les blocs de texte ;
- privilégier les repères visuels ;
- conserver une lecture rapide sur mobile.

---

# Informations prioritaires

Les informations suivantes doivent apparaître immédiatement :

- nom du tournoi ;
- dates ;
- lieu ;
- catégorie ;
- type de compétition ;
- état des inscriptions.

Ces informations constituent le premier niveau de lecture.

---

# Hiérarchie visuelle

Les informations sont organisées par importance.

Ordre recommandé :

1. Nom du tournoi
2. Dates
3. Lieu
4. Catégorie
5. Type
6. État des inscriptions

Les informations secondaires restent masquées tant que la carte est repliée.

---

# État des inscriptions

L'état des inscriptions est représenté par un indicateur visuel.

Les états suivants sont distingués :

- Inscriptions ouvertes
- Ouverture prochaine
- Inscriptions closes

L'indicateur doit être immédiatement identifiable.

La représentation exacte (badge, pastille, rond coloré…) reste libre tant qu'elle respecte les principes de simplicité et d'accessibilité.

---

# Dépliage

Le dépliage de la carte donne accès aux informations complémentaires :

- lien BadNet ;
- Google Maps ;
- Google Calendar ;
- mode d'inscription ;
- informations détaillées.

Aucune surcharge visuelle n'est introduite sur la carte repliée.

---

# Actions

Les actions sont regroupées dans la partie dépliée.

Ordre recommandé :

1. BadNet
2. Google Maps
3. Ajouter au calendrier

Les actions restent facilement accessibles sur mobile.

---

# Acronymes

Les acronymes peu connus des parents doivent être explicités.

Une aide contextuelle légère (par exemple une infobulle) pourra être utilisée lorsque cela améliore la compréhension sans surcharger l'interface.

---

# Responsive

Le comportement est identique sur :

- desktop ;
- tablette ;
- smartphone.

La carte reste facilement lisible sur les petits écrans.

---

# Performance

Les améliorations graphiques ne doivent pas augmenter perceptiblement le temps d'affichage.

La fluidité de navigation reste prioritaire.

---

# Architecture

Cette sous-issue concerne exclusivement la présentation.

Aucune règle métier n'est modifiée.

Aucune évolution du modèle Tournament n'est nécessaire.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouveaux filtres ;
- nouveaux tournois ;
- persistance des préférences ;
- analytics ;
- Google Calendar.

Ces sujets sont traités dans d'autres sous-issues.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- les informations principales sont immédiatement identifiables ;
- l'état des inscriptions est représenté visuellement ;
- les cartes restent compactes lorsqu'elles sont repliées ;
- les actions sont regroupées dans la partie dépliée ;
- les cartes sont lisibles sur mobile et desktop ;
- aucune régression fonctionnelle n'est observée.
