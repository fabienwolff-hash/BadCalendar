# BC-14.3 — Nouveaux tournois

# Objectif

Cette sous-issue introduit la notion de **nouveau tournoi** dans BadCalendar.

L'objectif est de permettre au parent d'identifier immédiatement les compétitions ajoutées depuis sa dernière visite.

Cette fonctionnalité améliore la découverte des nouvelles compétitions sans modifier le fonctionnement des filtres ou de la navigation.

---

# Contexte

Au cours de la saison, de nouveaux tournois sont régulièrement publiés.

Aujourd'hui, un parent doit parcourir toute la liste pour identifier les nouveautés.

Cette sous-issue permet de mettre automatiquement en évidence les tournois récemment ajoutés.

---

# Définition d'un nouveau tournoi

Un tournoi est considéré comme **nouveau** lorsqu'il apparaît pour la première fois dans le Master.

La date de cette première apparition est enregistrée dans la propriété :

```text
CreationDate
```

Cette date ne change jamais.

Les modifications ultérieures d'un tournoi ne le rendent jamais à nouveau "nouveau".

Par exemple :

- ajout d'une adresse ;
- correction d'une faute ;
- ajout des dates d'inscription ;
- modification des catégories.

Ces évolutions ne constituent pas une nouveauté.

---

# Gestion de CreationDate

Le Master comporte une nouvelle colonne :

```text
CreationDate
```

Cette colonne est renseignée automatiquement lors de la création d'un nouveau tournoi.

Un script Apps Script `onEdit(e)` détecte l'ajout d'un TournamentId et renseigne automatiquement la date du jour si `CreationDate` est vide.

Cette valeur n'est ensuite jamais modifiée.

---

# Gestion de LastVisit

Le navigateur mémorise localement :

```text
LastVisit
```

Cette information est enregistrée dans le Local Storage.

Elle est mise à jour à chaque ouverture de l'application.

Aucune donnée n'est stockée côté serveur.

---

# Détection des nouveautés

Le backend détermine si un tournoi est nouveau.

La règle métier est :

```text
CreationDate > LastVisit
```

Lorsque cette condition est vérifiée, la propriété suivante est ajoutée au modèle Tournament :

```javascript
isNew
```

Le frontend ne réalise aucun calcul.

---

# Première visite

Lors de la première ouverture de BadCalendar :

- aucun tournoi n'est considéré comme nouveau ;
- LastVisit est initialisé.

L'objectif est d'éviter que l'ensemble des compétitions soient marquées comme nouvelles.

---

# Affichage

Les nouveaux tournois sont identifiés par un badge :

```text
Nouveau
```

Le badge apparaît uniquement lorsque :

```text
isNew == true
```

Le style graphique reste cohérent avec le reste de l'application.

---

# Disparition du badge

Le badge disparaît automatiquement lors d'une visite ultérieure.

Aucune action de l'utilisateur n'est nécessaire.

---

# Architecture

Les responsabilités sont réparties comme suit.

Master :

- conserve CreationDate.

Apps Script :

- initialise automatiquement CreationDate.

Backend :

- calcule isNew.

Frontend :

- affiche le badge.

Chaque composant possède une responsabilité unique.

---

# Performance

La comparaison entre CreationDate et LastVisit est réalisée une seule fois lors de la construction du modèle Tournament.

Aucun calcul n'est effectué lors de l'affichage des cartes.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- notifications ;
- historique des modifications ;
- suivi des mises à jour d'un tournoi ;
- nouveautés de l'application ;
- analytics.

Ces fonctionnalités pourront être étudiées ultérieurement.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- CreationDate est automatiquement renseignée ;
- LastVisit est correctement mémorisé ;
- isNew est correctement calculé ;
- seuls les nouveaux tournois affichent le badge ;
- une modification d'un tournoi existant ne recrée jamais un badge "Nouveau" ;
- le comportement est identique sur desktop et mobile.
