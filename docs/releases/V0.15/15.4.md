# BC-15.4 — Finalisation et stabilisation

# Objectif

Cette sous-issue finalise la version v0.15.

Elle consiste à vérifier le bon fonctionnement des filtres avancés, leur cohérence sur l'ensemble de l'application et leur conformité avec les spécifications définies pour cette version.

Aucune nouvelle fonctionnalité n'est développée dans cette sous-issue.

---

# Contexte

Les sous-issues précédentes ont permis :

- l'évolution du modèle de filtres ;
- l'implémentation du moteur de filtrage multi-valeurs ;
- l'intégration des nouveaux composants d'interface.

Cette dernière étape garantit la qualité de l'expérience utilisateur avant la clôture de la version.

---

# Vérifications fonctionnelles

Les scénarios suivants doivent être validés.

## Sélection multiple

Vérifier que plusieurs valeurs peuvent être sélectionnées simultanément pour :

- Catégorie ;
- Type ;
- Portée ;
- État des inscriptions.

Le filtre Mois doit conserver une sélection unique.

---

## Combinaison des filtres

Vérifier que :

- plusieurs valeurs d'un même filtre sont combinées avec un opérateur **OU** ;
- plusieurs filtres sont combinés avec un opérateur **ET**.

Les résultats doivent être conformes aux règles métier.

---

## Filtre inactif

Vérifier qu'un filtre sans valeur sélectionnée n'a aucun impact sur les résultats.

---

## Réinitialisation

Vérifier que le bouton **Réinitialiser les filtres** :

- supprime toutes les sélections ;
- supprime les préférences persistées ;
- restaure les valeurs par défaut.

---

## Persistance

Vérifier que les filtres persistés :

- sont correctement restaurés au démarrage ;
- conservent toutes les valeurs sélectionnées.

Les filtres non persistés restent réinitialisés.

---

## Interface utilisateur

Vérifier que :

- les ChipFilters restent lisibles ;
- le ChecklistFilter est simple à utiliser ;
- les résumés des filtres sont corrects.

---

## Responsive

Vérifier le comportement sur :

- smartphone ;
- tablette ;
- desktop.

Les filtres doivent rester facilement manipulables au doigt.

---

# Robustesse

Vérifier notamment que :

- aucune erreur JavaScript n'est générée ;
- aucune régression fonctionnelle n'est observée ;
- le temps de réponse reste instantané.

# Release Checklist

Avant de clôturer la sous-issue, vérifier notamment :

- les critères d'acceptation des BC-15.1 à BC-15.3 sont validés ;
- les scénarios fonctionnels sont passants ;
- la documentation est à jour ;
- aucune anomalie bloquante n'est identifiée.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouveaux critères de filtrage ;
- Usage Metrics ;
- optimisation des performances ;
- nouvelles fonctionnalités utilisateur.

Toute évolution supplémentaire sera planifiée dans une version ultérieure.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- les filtres multi-valeurs fonctionnent conformément aux spécifications ;
- les composants ChipFilter et ChecklistFilter sont correctement intégrés ;
- le comportement est identique sur desktop et mobile ;
- aucune anomalie bloquante n'est identifiée ;
- la documentation est synchronisée ;
- la Release Checklist est validée.

La version v0.15 peut alors être clôturée.

---

# Livrable attendu

À l'issue de cette sous-issue :

- BadCalendar dispose d'un système de filtres avancés simple et performant ;
- les recherches sont plus flexibles sans complexifier l'interface ;
- l'expérience utilisateur reste fluide sur tous les supports ;
- la documentation est à jour ;
- la version v0.15 est prête à être livrée.
