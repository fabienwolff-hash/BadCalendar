# BC-15.3 — Intégration des filtres avancés

# Objectif

Cette sous-issue intègre les filtres multi-valeurs dans l'interface utilisateur de BadCalendar.

L'objectif est de proposer une expérience de filtrage simple, rapide et adaptée au mobile, tout en tenant compte du nombre de valeurs disponibles pour chaque filtre.

Aucune évolution du moteur de filtrage n'est réalisée dans cette sous-issue.

---

# Contexte

Les filtres constituent le principal moyen de retrouver rapidement une compétition.

Tous les filtres ne présentent cependant pas le même nombre de valeurs.

Une interface unique ne permettrait pas d'offrir la meilleure expérience utilisateur dans tous les cas.

Cette sous-issue adapte donc la représentation graphique de chaque filtre à son usage.

---

# Principes UX

Les filtres respectent les principes suivants :

- filtrage instantané ;
- aucune validation supplémentaire ;
- aucun bouton "Appliquer" ;
- fonctionnement intuitif ;
- priorité à l'expérience mobile.

Le filtrage est appliqué immédiatement après chaque modification.

---

# Répartition des composants

Deux composants de sélection sont utilisés.

## ChipFilter

Les filtres comportant peu de valeurs utilisent des pastilles sélectionnables (chips).

Ils concernent :

- Catégorie ;
- Portée ;
- État des inscriptions.

Ces filtres restent visibles en permanence.

---

## ChecklistFilter

Les filtres comportant de nombreuses valeurs utilisent une liste de cases à cocher.

Ce composant est utilisé pour :

- Type de compétition.

Le contenu est affiché uniquement lors de l'ouverture du filtre.

---

# Sélection

Chaque valeur peut être :

- sélectionnée ;
- désélectionnée.

Plusieurs valeurs peuvent être actives simultanément.

Chaque modification déclenche immédiatement un nouveau filtrage.

---

# Résumé des filtres

Lorsqu'un filtre est replié, un résumé est affiché.

Exemples :

```text
Type (3)

ou

Type : TRJ +2
```

Le résumé permet de connaître rapidement les critères actifs sans rouvrir le filtre.

---

# Persistance

Les préférences utilisateur continuent de fonctionner.

Lorsque le filtre est persistant, l'ensemble des valeurs sélectionnées est mémorisé dans le Local Storage.

Les filtres non persistés restent réinitialisés au démarrage.

---

# Réinitialisation

Le bouton **Réinitialiser les filtres** :

- désélectionne toutes les valeurs ;
- supprime les préférences persistées ;
- restaure les valeurs par défaut.

Le comportement reste identique aux versions précédentes.

---

# Responsive

L'interface est optimisée pour :

- smartphone ;
- tablette ;
- desktop.

Les zones tactiles restent suffisamment grandes pour être utilisées au doigt.

---

# Accessibilité

Les valeurs sélectionnées sont immédiatement identifiables.

Le contraste visuel doit permettre de distinguer facilement :

- une valeur active ;
- une valeur inactive.

Les composants restent utilisables sans apprentissage.

---

# Performance

Le changement d'un filtre met immédiatement à jour la liste des compétitions.

Le temps de réponse doit rester imperceptible pour l'utilisateur.

---

# Architecture

Le frontend est responsable :

- de l'affichage des composants de sélection ;
- de la collecte des valeurs choisies ;
- de l'appel au FilterService ;
- de l'affichage des résultats.

Le moteur de filtrage reste entièrement indépendant de l'interface graphique.

---

# Hors périmètre

Cette sous-issue ne comprend pas :

- nouveaux critères de filtrage ;
- modifications du moteur de filtrage ;
- analytics ;
- nouvelles préférences utilisateur.

Ces évolutions seront étudiées dans d'autres versions.

---

# Critères d'acceptation

La sous-issue est considérée terminée lorsque :

- les filtres Catégorie, Portée et État utilisent un composant ChipFilter ;
- le filtre Type utilise un composant ChecklistFilter ;
- le filtre Mois conserve son fonctionnement actuel ;
- les filtres sont appliqués instantanément ;
- les préférences persistées continuent de fonctionner ;
- le bouton "Réinitialiser les filtres" fonctionne correctement ;
- le comportement est identique sur mobile et desktop ;
- aucune régression fonctionnelle n'est observée.
